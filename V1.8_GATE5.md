# Hashtag V1.8 Gate 5 — Checkpoint / Resume

When a multi-step Body operation pauses because permission is required, Hashtag
stores the exact OperationGraph state and resumes that same graph after approval.

Flow:
Request → Brain plans once → OperationGraph → op_1 SUCCESS
→ op_2 permission_required → checkpoint saved
→ user approves → /v1/request/resume
→ same graph restored → op_1 is NOT executed again
→ op_2 executes → graph completes

New/updated files:
- checkpoint_store.py
- operation_graph.py
- operation_graph_executor.py
- server.py
- test_v18_gate5_checkpoint_resume.py

New endpoints:
- POST /v1/request/resume
- GET /v1/checkpoints/<checkpoint_id>

Convenience:
- POST /v1/request with {"checkpoint_id": "..."} also resumes.

The checkpoint store is intentionally in-process for this gate. A Core server
restart clears active checkpoints. Durable persistence can be added later
without creating another planner or execution engine.

The existing Hashtag Brain, BodyRouter, BodyClient, OperationGraph,
OperationGraphExecutor, verifier/recovery, and MemoryStore architecture remains
the same.
