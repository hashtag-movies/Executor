# Hashtag Core — V1.8 Gate 2

## Brain → OperationGraph compatibility adapter

V1.8 Gate 2 adds the first bridge between the existing Hashtag Brain/V10
planning output and the V1.8 OperationGraph contract.

### Architecture

```text
Natural language + data
        ↓
Existing HashtagBrain.plan()
        ↓
Existing V10 actions
        ↓
Existing V11 Operation contract
        ↓
V1.8 OperationGraph adapter
        ↓
OperationGraph
```

### Important constraints

Gate 2 does **not**:

- create another planner
- create another brain
- replace `HashtagBrain.plan()`
- execute operations
- route to a Body
- change permissions
- change verification
- change recovery
- change the existing V10 action format

The adapter is deliberately isolated so V1.7 behavior remains unchanged.

The adapter exposes the original plan plus:

- `operationGraph`
- `graph`
- `pipeline = "1.8-G2"`

The graph itself remains version `1.8-G1`.

### Dependency behavior

When the Brain returns multiple actions and no explicit dependency metadata is
available yet, `OperationGraph.from_operations()` creates the existing
deterministic linear dependency chain:

```text
op_1 → op_2 → op_3
```

This is intentional for Gate 2. True semantic dependency planning belongs to a
later gate.

### V10 compatibility

Legacy action dictionaries are converted using the existing authoritative
`Operation.from_action()` compatibility path. No duplicate action-to-operation
conversion logic is introduced.

### Gate 2 acceptance criteria

- one Brain action becomes one graph node
- multiple Brain actions become an ordered graph
- V10 action fields remain lossless
- graph serialization round-trips
- empty plans remain valid
- real HashtagBrain output can pass through the adapter
- existing V1.7 behavior remains untouched
